# 多机器 DSH 实现计划

[English](multi-machine-plan.md) | 中文

此工作面向五个独立的 DSH Web 实例：一台 Linux 主机和四台通过 Tailscale 连接的 Windows 主机。每个实例保留自己的会话、凭据、模型配置和代码检出目录。首个实现是可选实验插件；现有本地 Agent Teams 保留当前行为。

## 研究发现

- `packages/client/connection` 为每个 Context 管理一个浏览器连接，并将请求认证为一个操作员。它不是 Harness 之间的授权协议。
- `packages/experimental/agent-team/src/roster.ts` 认证精确的本地 Agent 对象；`subagent/src/continuation-activation.ts` 创建本地 Agent。远程成员需要显式归属，不能伪装成本地延续。
- `packages/storage/storage-domain` 提供经过验证的持久记录和串行记录更新。`agent/inbox/spliced` 提供持久接收证据，无需引入模型可见的旁路。
- `packages/host/webserver` 支持由 effect 管理的路由。独立认证的对等路由可以与浏览器应用共存，无需削弱其同源检查。
- SSH 提供方将文件系统与进程执行移到 POSIX 主机，同时保留本地 Harness。它们不满足独立 Windows Harness 参与团队的要求。

## 实现顺序

1. 添加持久环境身份和描述符。对等调用绑定预期环境；在执行前验证协议、端点、授权和配置的工作区别名。
2. 添加具有单一协调者的显式分布式团队。通过 storage-domain 持久化名册、任务、幂等命令回执和待处理消息。传输失败后保留可重试工作。
3. 为传入成员创建独立本地 Session。将部署拥有的项目别名映射到本地绝对目录。先持久化分配，再创建 Session；收件箱刷盘后才确认投递。重启后协调待投递消息。
4. 将环境发现和分布式团队操作作为模型工具提供。远程参与者通过经过身份验证的对等请求访问协调者。本地 Web 视图显示普通 Session 记录和工具结果。
5. 验证身份初始化、认证拒绝、端点身份不符、权限隔离、幂等创建与投递、修订冲突、断线、重启和生命周期清理。添加真实 Loader 组合测试及记录的模型可见输出。
6. 将运行时与插件配置页面打包。通过 profile 编辑器保存任意对端身份和 URL、检出目录映射、工作端默认值及限制；通过凭据服务保存密钥。每个团队由主 Session 所在机器协调。验证重新加载与重启后的保存值、并发编辑拒绝、密钥轮换及页面生命周期。
7. 记录配置与经过测试的部署路径，更新双语包参考，运行定向行为、类型和文档检查，并明确记录尚缺的平台部署证据。

## 后续实现顺序

1. 工作区管理已部署到配对的 Windows 和 Linux 主机：环境面板在显式对端授权和规范路径检查下浏览目标目录、创建文件夹并注册工作区。
2. 由目标实例拥有的 Session 创建、列表、已保存文本聊天、取消和重连刷新已部署到配对主机。经过身份验证的实时文本流已在此分支实现，但尚未部署：受限快照包含尚未完成的助手文本，重连时使用目标实例的快照替换视图，目录轮询保持独立，断线期间保留最后收到的文本。接下来，通过各环境拥有的客户端服务添加附件、审批回复、终端和普通对话导航。
3. 分布式团队仪表板：在 GUI 中投影协调者拥有的名册、带修订号的任务、投递状态和中断。区分远程成员与本地 Agent 句柄，并明确显示协调者断线状态。
4. 配对生命周期：添加一次性邀请和可独立撤销的授权，同时保留插件页面中的直接 Tailscale 配置。验证重放拒绝、过期、权限收窄和凭据轮换。
5. 物理部署：升级已配对的 Windows 和 Linux 主机，验证真实跨机器团队及重启恢复，再配置其余三台 Windows 主机。记录每台主机的实际可达性和执行证据；环回夹具不足以完成验收。

## 初始协议限制

每个团队由一个环境拥有；不包含协调者故障转移和自动任务重新分配。远程智能体从新上下文开始。文件绝不隐式同步：主机将项目别名映射到独立检出目录，并交换提交或补丁。将浏览器聚合为统一多环境侧栏是独立客户端功能；本次迭代保留每台主机上的 DSH Web。

## 验收

负责人可以在已配对环境上启动成员、交换持久消息，并共享带修订检查的任务。重试结果不确定的命令不会创建额外成员或收件箱项目。环境身份错误、缺失对等权限和未配置工作区都会拒绝操作。所有模型输入仍保留在目标 Session 日志中。移除配置授权后，后续操作被拒绝。断线不表示取消或任务完成。

部署选项必须可在插件页面编辑，无需修改源码或设置部署环境变量。代码不固定主机名、检出路径、机器数量或协调端。
