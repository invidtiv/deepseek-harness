# Agent Note: ACP 命令控制

Status: implemented

[English](2026-10-17-acp-command-control.md) | 中文

## 问题

ACP 客户端需要确定性地控制持久目标。将 `/goal` 作为普通模型输入发送会消耗模型请求，并把执行交给模型解释，而共享配置已经挂载命令与目标服务。

## 决策

ACP 通过标准发现与文本提示词分发公开接收 Agent 已注册的命令。现有命令处理器负责验证、领域变更和持久命令记录。桥接层交付直接文本结果，不把命令文本插入模型历史。此决策仅取代 [ACP 作为仅面向自动化的协议](../simplification/2026-07-23-acp-automation-only-protocol.zh.md)中的命令排除项；该说明仍负责传输与展示限制。

命令完成与目标完成是两回事。命令可在 Agent 运行时控制目标；自动轮次保留正常的 Agent 取消和拆卸机制。V2 报告自主活动，并为命令回显及结果使用仅在实时连接中有效的消息标识。命令记录仍持久保存，但这些回显不会重放。

## 考虑过的替代方案

**继续让模型解释命令。** 这无法在不消耗模型轮次的情况下提供确定性的查看、暂停或变更。

**恢复交互式 UI 桥接层。** 目标控制需要命令分发与文本结果；编辑器卡片、选择器和 Harness 展示元数据增加了职责，却不服务于此需求。

**在 ACP 内实现目标解析。** 复用命令注册表可让各客户端保持相同的语法和领域检查。

## 后果

ACP 获得直接目标控制，而领域行为保留在现有所有者中。已注册的斜杠前缀现在调用命令，因此要与模型讨论这些命令，客户端必须将其放入普通语句。命令请求仅接受文本；附件在执行前失败。协议测试覆盖目标变更、自动轮次、取消、并发控制、恢复和拆卸；随附配置快照固定直接目标输出。
