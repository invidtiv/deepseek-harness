# Agent Note: ACP 进度与历史

Status: implemented

[English](2026-10-18-acp-progress-and-history.md) | 中文

## 问题

自动化客户端在重新连接后需要保留的对话历史和进度。仅靠命令确认无法描述后续自主目标工作，而任务列表已有持久表示。

## 决策

ACP 投影现有目标和待办状态，不增加第二套领域模型。标准助手文本传递当前目标阶段、激活状态、轮次数及阻塞原因；标准计划更新传递完整待办列表。恢复目标会报告未启用状态，不会重启工作。V1 历史加载与 v2 回放通过分页持久化读取保留对话消息标识。

这取代了 [ACP 作为纯自动化协议](../simplification/2026-07-23-acp-automation-only-protocol.zh.md)对历史加载和任务计划的排除。[命令控制](2026-10-17-acp-command-control.zh.md)仍负责命令派发。编辑器卡片、计划文档审阅、终端及客户端文件系统访问仍不属于此传输。

提供方共享使用现有的主目录补丁层。一份完整适配器配置服务于所有消费配置档；配置档本地模型选择与共享凭据引用仍彼此独立。不引入隐式 Web 配置档导入或第二套配置存储。

## 考虑过的替代方案

私有目标协议会让基本进度依赖客户端专门支持。标准文本可用于现有客户端，而目标服务保留结构化状态。将 Web 提供方设置复制到 ACP 会留下两个逐渐偏离的数据源；主目录补丁已提供有序共享配置。

## 影响

客户端独立于命令完成接收目标更新。V1 加载回放保留历史，恢复则重建当前进度而不回放转录。录制会话与真实配置档测试覆盖这些区别；T3 探针使用稳定 v1，因为受测通用运行时不会将 v2 整条消息文本投影到其事件流。
