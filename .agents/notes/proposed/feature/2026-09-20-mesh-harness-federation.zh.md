# Agent Note：Mesh —— Harness 实例之间的配对与联邦

Status: proposed

[English](2026-09-20-mesh-harness-federation.md) | 中文

## 问题

运维者在由私有网络连接的不同机器上运行多个 DeepSeek Harness 实例，希望它们互相知晓、共享会话并互相驱动。peer 家族已经承载了控制面：`ctx.peers` 是接缝，`dsh-peer-remote` 是 HTTP 传输，`dsh-tool-peer` 暴露 `peer_ask`、`peer_sessions` 与 `peer_transcript`。

它没有承载的，是机器能够自行获取的凭据。该传输使用对端的浏览器会话 cookie 认证；该 cookie 由 HMAC 签名、绑定到唯一权威、只能通过 `GET /?token=<每进程启动令牌>` 铸造，且从不持久化。因此，配对两个实例意味着：从对端控制台读出令牌、在浏览器中打开它的 URL、提取 cookie，再粘贴到环境变量里。这既不安全也无法自动化，而且对端重启或地址变更时就会失效。

同一根因还带来另外三个缺口。节点没有非交互式身份，因此无法验证对端确实是它声称的那个对端。对端没有实时会话视图，因为传输只轮询一个已结算的回合。而且该凭据授予对端 Remote API 所授予的一切，没有更窄的策略可用。

## 提案

新增 `packages/mesh/` 家族，实现**节点身份、基于安全配对码的握手，以及位于封闭操作集之前的策略执行监听器**。

**监听器独立且需显式启用。** `dsh web` 拒绝 `--host 0.0.0.0`，因为它的 `/api` 面是完整的、具备工具能力的 Host API；而 `ctx.webServer` 的 schema 没有任何可供 Tailscale 接口绑定的地址。因此 mesh 拥有自己的 `node:http` 服务器：在出厂组合中处于禁用状态，可绑定 unix socket、环回地址或节点自身的 Tailscale 地址，绝不绑定其他地址。

**配对采用 SPAKE2（RFC 9382），基于 edwards25519。** 响应方显示八符号 Crockford 配对码；发起方通过带外渠道获知。双方人类比对由协商密钥派生的六位短认证串，响应方批准，随后双方各自向对方交付一个在该密钥下密封的长期 bearer 令牌。被记录的会话记录不产生离线验证器——而把配对码混入 KDF 的普通 Diffie-Hellman 交换做不到这一点。配对码绝不从命令行参数或模型工具调用中接受，因为工具调用是持久的、模型可见的历史。

**授权只依据配对令牌，别无其他。** 在 `tailscale serve` 拓扑下，后端的对端是本机代理；Tailscale 文档明确说明，任何能直接到达后端的进程都可以伪造 Serve 的身份头；对 Funnel 流量这些头不存在，对带标签设备也不填充。因此 mesh 仅把代理提供的身份记为*声称的*身份，用于展示与审计，绝不据此授权。按来源限速与来源固定只在直连 Tailscale 绑定时存在，设计对此直言不讳，而不是施加无法生效的控制。

**会话由其所有者提供，绝不挂载。** 节点通过既有的 `ctx.connection.authenticatedUrl` 宿主 API 铸造自己的内存内环回浏览器会话，代表对端驱动自己的 `/api`，并由授权过滤。实时跟随、取消与搜索都来自已经存在的 Remote 方法。两个 harness 绝不写入同一份会话日志，被跟随的远端会话是独立的只读视图，而不是追加到本地日志的事件。

**授权不是隔离，提案明确说明这一点。** `cwd` 允许列表只约束请求可以*指名*的目录；在允许目录内启动的 agent 可以用普通工具访问其他地方，而针对既有会话的 prompt 根本不会指名任何 `cwd`。因此会话操作依据会话自身记录的元数据授权，并且包含写操作的授权必须指名一个实施隔离的权限预设或执行世界。出厂默认不授予任何写操作。

## 考虑过的替代方案

**放宽 Web GUI 的监听器。** 拒绝：这会重新引入 peer 控制面笔记所拒绝的确切暴露，而且该面上的 `/plugins/*` 与静态资源本来就无需认证。

**用 `tailscale serve` 发布 GUI 并继续使用 cookie。** 仅保留为未来的兼容模式：它仍需要人工采集 cookie，而泄露的 cookie 就是对端的整个 API。

**通过 SSH stdio 驱动对端。** peer 笔记已经拒绝：每次调用都要新建远端进程、每个对端都要强制命令，且会话列表与转录读取没有等价物。

**通过网络文件系统共享 `$DSH_HOME/sessions`。** 拒绝：单写者保证在 POSIX 上是内核 `flock`，在 Windows 上是按登录会话命名的信号量；`flock` 在 NFSv3 上不可靠；存储会拒绝混用压缩后缀的根目录；派生的搜索索引被明确记录为单一所有者。

**用 OPAQUE 取代 SPAKE2。** `@serenity-kit/opaque` 是唯一经过独立白盒审计的 npm PAKE，但它属于错误的协议族：OPAQUE 是增强型 PAKE，其目的是保护存储的注册记录，而本流程不存储任何东西。RFC 9382 第 7 节指出需要增强的场景应使用 OPAQUE，而 SPAKE2 不支持增强。若第三方审计的二进制成为硬性要求，它被列为回退方案。

**把配对码混入的手工 X25519 加 HKDF 构造。** 拒绝：它留下的会话记录可以针对全部 40 位配对码离线攻击。短认证串能检测主动中继，但检测不了离线破解。

**信任 tailnet 并跳过应用层认证。** 作为唯一控制被拒绝：tailnet 可能包含运维者无法控制的带标签设备；ACL 表达的是可达性而非操作；而在 Serve 拓扑下 `tailscale whois` 需要后端并不拥有的地址。

## 验收标准

- 两个全新安装通过一次配对码传递完成配对；配对码绝不出现在命令行、日志、审计记录或线路上；使用同一配对码的第二次尝试失败。
- 记录整段交换但不知道配对码的攻击者无法完成配对，且双方人类看到的短认证串不同。
- 已配置节点被列出，包含身份、端点、配对状态与最近一次成功联系，并在停止后被标记为不可达。
- 一个节点拥有的会话可以被列出、读取、在运行期间实时跟随、在流中断后从游标恢复且无缺口无重复，并可由另一节点发出的 prompt 驱动。
- 在一个节点上撤销后，该节点在下一个请求即停止接受对端；远端清理需认证且为尽力而为。
- 每个跨节点失败都报告来自同一张表的代码，本地持久审计则区分调用方被刻意不告知的信息。
- 每个节点上的 Web GUI 都绑定环回，并通过探测实际正在运行它的机器来验证。

## 风险

握手是安全核心，其中静默的缺陷是最坏的后果；RFC 9382 附录 B 的向量会针对本实现运行，edwards25519 常量则与公布值比对。允许未指定隔离预设的写操作的授权就是远程代码执行，因此出厂默认不授予任何写操作，且缺少具名预设时加载会失败。逐字节复制的节点主目录仅凭持有无法与原节点区分，因此克隆检测仅限于分歧，运维手册规定复制时删除身份。参考 tailnet 上没有 macOS，其行为依据源码规定而未经实测。传输在 WireGuard 之内是基于 bearer 令牌的，因此已持有令牌的一方重放请求在设计上就是可能的；写操作通过幂等键缓解，并通过审计使其可见。
