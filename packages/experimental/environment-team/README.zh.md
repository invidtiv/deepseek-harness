# @deepseek-ai/dsh-experimental-environment-team

[English](README.md) | 中文

## 概述

这个可选插件可以在其他 Harness 实例上创建队友，并共享消息和带修订号的任务。每个实例保留自己的凭据、模型路由、会话和代码检出目录。每个团队由一个环境负责协调；成员断线不会释放其已分配的任务。每台机器的普通 Web UI 显示本地 Session 和工具结果。

## 使用此包

在包含持久 Session 存储、storage-domain、Agent 循环和工具的 Web 组合中挂载此插件。它可以与本地 Agent Teams 共存，但分布式成员使用 `environment_team`，并属于独立的分布式名册。在插件页面将此包安装为组合包，然后编辑其跨环境团队页面。运行时和操作员配置服务是独立的条目，因此保存运行时设置不会移除配置服务。

### 配置

将 `stateDirectory` 设为此实例独占的私有绝对目录，并显式指定 `label`、`provider` 和 `model`。`workspaces` 把项目别名映射到已存在的本地绝对目录。负责人 Session 必须使用其中一个目录。目标环境使用自己的映射、文件系统和模型路由；模型凭据不会在实例之间复制。

每个 `peers` 项包含 `environmentId`、以 `url` 表示的 HTTPS 来源、凭据引用 `tokenEnv`，以及 `workspaces` 中允许的项目别名。在插件页面为两端分别配置对方身份和同一个独立生成、至少 32 字节的密钥。凭据存储负责密钥值；每次操作读取当前值，因此轮换无需重启。每一对环境使用不同密钥。此令牌授予主机级团队参与权限，以及在所配置工作区别名内执行远程工作的权限；它不是用户级或只读凭据。远程智能体使用目标环境组合的工具和沙箱策略。移除对等项并保存配置后，后续请求会被拒绝；已经授权的工作不会自动取消。

显式配置 `agentPreset`、`sandboxMode` 和 `approvalPolicy`。新成员在发布前挂载该本地预设并记录权限设置，然后关联本地 Workspace 以供 Web 导航。恢复的成员使用持久化的预设选择与权限，以及配置的本地默认模型路由。

`GET /.well-known/dsh/environment` 返回实例持久化的 UUID、标签、平台、协议版本和能力标志。只有通过可信管理渠道获得 UUID 后，才应配置该对等端。发现接口公开可读，但不授予权限。每次出站操作都会先验证描述符，再发送凭据；重定向会被拒绝，响应身份也会被验证。本地集成允许使用字面量环回地址的 HTTP，其他来源必须使用 HTTPS。对等路由拒绝带浏览器 Origin 或 Fetch-Metadata 头的请求，也不复用浏览器操作员 cookie。

| 字段 | 默认值 | 含义 |
|---|---|---|

| `maxBytes` | `1048576` | 团队记录、带框架消息、HTTP 请求或响应的大小上限 |
| `maxTeams` | `64` | 本环境协调的团队数量上限 |
| `maxMembers` | `16` | 每个团队的成员上限，包括负责人 |
| `maxTasks` | `256` | 每个团队保留的任务数量上限 |
| `maxOperations` | `2048` | 每个团队保留的修改命令回执数量上限 |
| `workspacePageSize` | `100` | 每个工作区响应中根目录、已注册工作区或目录条目的数量上限 |
| `sessionPageSize` | `100` | 每个响应中的 Session 摘要或已保存文本消息数量上限 |
| `sessionSyncIntervalMs` | `2000` | Session 目录刷新及断线跟随重试间隔 |
| `sessionStreamHeartbeatMs` | `2000` | 对等流心跳及凭据重新检查间隔 |

### 工作区浏览器

**环境**面板按持久身份列出已配置实例，并保留不可用的条目。选择实例可查看其已注册工作区并浏览获授权的目录。文件夹创建和工作区注册在目标实例上执行；对端不可用时绝不会回退到本机。刷新失败会保留已加载视图，先前选中实例的响应不能替换当前视图。

在目标实例上，启用调用方对端的 `workspaceManagement` 权限以允许这些操作；默认值为 `false`。该对端的 `workspaces` 授权将目录访问限制为已配置别名及其规范化子目录。路径穿越和指向根目录之外的符号链接会被拒绝。目录元数据包含目标路径；不返回文件内容或凭据。重复创建文件夹或注册同一目录会复用现有目录或工作区。`workspacePageSize` 显式截断列表，`maxBytes` 限制完整编码响应的大小。

两端实例都必须声明工作区浏览能力。注册嵌套工作区不会添加团队别名；将该目录用于分布式团队的负责人工作区前，应先将其配置为别名。

### 工作区 Session

在目标实例上启用调用方对端独立的 `sessionAccess` 授权，即可在获准工作区中列出、创建、读取普通 Session、提交文本以及停止会话。此权限默认值为 `false`；工作区管理权限不包含会话访问权限。目标实例必须声明 `workspaceSessions`，此能力要求其 Session Controller 可用。新会话使用配置的智能体预设和目标实例普通 Web 的模型与权限默认值；团队工作端的模型设置不会覆盖这些值。

在已注册工作区上选择**打开会话**。面板从目标实例跟随已保存的用户和助手文本、尚未完成的助手文本以及运行状态。断线期间保留最后视图；重连时用目标实例当前的已保存消息和活动助手文本前缀替换该视图。目录刷新和提示提交不会重新启动选定的流。目标实例始终独占其 Session 日志、凭据、执行和文件。每个请求包含环境与工作区身份；远程 Session ID 不会进入本地对话控制器。创建和提示重试保留操作身份，以免在响应不确定后重复接纳。

两端实例都必须支持 `workspaceSessionFollow` 才能显示实时文本。跟随冷 Session 可能在目标实例上激活它；关闭面板会释放订阅，但不会取消 Agent。完整替换帧具有可配置的消息数量和字节限制，速度较慢的对端会收到最新可用视图。停止 Session 会请求中断活动工作，并保留排队的收件箱。重新加载配置会关闭活动流；轮换凭据会在下次心跳检查时关闭活动流。已接纳的工作仍继续运行。

对话控件显示已提交的工具结果和错误。目标端独立的 `attachmentAccess`、`approvalAccess` 和 `terminalAccess` 授权默认均为 `false`。附件上传到所属 Agent 的暂存回执中；图片以图片形式进入模型请求。下载要求获准 Session 日志中存在对应引用。提示重试指纹保存在 `stateDirectory/prompt-receipts` 下，在回执过期后仍会拒绝内容发生变化的提交。待处理审批和问题共用普通 Web 的答复处理服务，因此多个查看者中首个有效答复生效。

终端以目标机器用户的权限执行，查看者断开后仍保留在该机器上。连接先接收恢复屏幕，再按顺序接收输出；查看者队列超过上限时必须重新连接。只有当前终端连接可写入或调整尺寸。终端输入不会自动重放。目标端终端服务负责进程限制和保留时间；显式关闭终端会停止该进程。

### 配对邀请

在插件页面保存每台机器可访问的 `publicUrl`。使用目标机器的身份、地址和明确的本机授权创建邀请，再私下将其传递到该机器的插件页面。接受邀请时选择反向授权。邀请绑定身份且仅可使用一次；列表读取仅包含元数据，不包含邀请密钥。响应丢失后可使用相同邀请和授权重试。如果配置提交状态不确定且对端已被移除，重试会拒绝恢复连接；重新开始前先丢弃未完成的接受记录。移除已配置对端可撤销其访问权限，与邀请过期无关。手动修改密钥会暂存新的凭据引用，并与配置修订一起提交。

### 团队操作

`environment_list` 列出本地身份、工作区别名和已配置对等端，不包含凭据或本地路径。`environment_team` 支持 `list`、`spawn`、`send`、`task-create`、`task-update` 和 `interrupt`。只有负责人能创建或中断队友。成员可以向 `lead` 或其他不可变成员名发送消息，也可以创建或认领共享任务。任务更新必须携带已观察到的修订号；冲突更新会被拒绝。成员不能修改另一成员拥有的任务，而负责人可以通过释放和认领管理任务归属。完成任务前，任务必须处于进行中状态。

spawn 或 send 的结果确认的是持久入队，不是执行或完成。协调者重试待投递消息。目标环境根据 Session 日志去重消息接收，重启后仍然有效，并且仅在日志刷盘后确认。使用相同工具调用身份和参数重试，会返回已提交的修改结果；改变参数则会拒绝。新的工具调用是新的命令。中断成员会保留其待处理收件箱；中断结果表示已经观察到请求，不保证远程执行已经停止。

### 操作员团队面板

协调器通过 `environmentTeamSettings.teamDashboard` 提供目录与详情读取。读取不会创建团队、成员关系或 Session。详情响应包含成员列表、带修订号的任务，以及带有发送者和目标名称的排队投递标识；投递正文与修改回执保持私有。对等环境需要 `teamAccess`，且授权别名中必须包含协调器负责人的工作区别名。查看成员列表不会授予成员工作区的访问权限。中断非负责人成员还需要 `teamOperate`；协调器直接验证操作员权限，不会将操作归因于 Agent。两个授权字段均默认为 false。本地操作员复用同一个活动运行时，不会另行打开持久存储。

### 存储与部署

将身份目录、storage-domain 数据和 Session 持久存储作为一个实例的状态共同管理。不要复制运行中的实例来创建另一台机器：应配置独立状态和身份。独占心跳锁会拒绝同时占用身份目录的进程。存储域也记录环境身份，并在重新打开时拒绝不同身份。身份文件损坏会使激活失败，而不会生成替代身份。

在 Tailscale 部署中，每台机器使用一个私有 HTTPS 反向代理端点，并保留 DSH 的环回监听。浏览器访问还需要普通 Web 的可信主机和身份验证配置。集成测试使用真实的环回 HTTP 服务器；通过 Tailscale Serve 部署，以及混合 Linux/Windows 机器集群，仍需要单独的运维验证。此插件不包含公共中继、共享数据库或自动文件同步。

## 理解实现

<details>
<summary>实现内部机制 — 点击展开</summary>

协调者将每个团队的名册、任务列表、待发送消息和命令回执存入同一条经过验证的 storage-domain 记录。修改会同时提交结果和重试回执。接收方先写入成员分配，再创建 Session，因此响应不确定时可以恢复同一目标 Session。消息身份包含协调者、团队、发送者和操作身份。传入消息使用 `environment-team` 来源，记录协调端、团队和发送方归属，不属于直接人类输入。回执投影折叠现有收件箱事件，不引入额外的未记录模型输入。运行时拥有创建的 Agent 句柄，并在释放存储和环境锁之前等待这些智能体停止。

[协议](src/protocol.ts)验证网络与持久记录，[运行时](src/runtime.ts)负责团队授权和状态，[传输层](src/transport.ts)负责有大小限制的身份验证请求。[身份发布器](src/identity.ts)通过独占硬链接发布文件，使并发初始化者收敛到一个完整的 UUID 文件。

</details>

## 模型体验

### 分布式团队协作

#### 模型看到的内容

两个工具返回 JSON 文本，描述已配置环境、团队成员、排队消息和带修订号的任务。投递消息包含团队、协调者、接收者和发送者，然后是原始文本及使用 `environment_team` 的说明。这些消息是普通的、已记录的 user 角色输入。Web 中的通用工具卡片显示相同结果；不会把远程文件系统路径当成本地 UI 路径。

#### Token 影响

工具 schema、工具结果和投递文本占用接收模型的上下文。每个远程成员承担独立新会话的 token 开销。

#### KV Cache 影响

消息追加到每个成员独立的历史中。机器之间不共享会话前缀或提供方缓存。

## 已知限制与后续工作

<a id="known-limitations-and-deferred-work"></a>

- 协调者必须恢复后，权威任务更新和成员消息才能继续。没有负责人选举、故障转移、自动重新分配或 Session 迁移。
- 远程成员从新上下文开始。成员交换文本、提交或补丁；插件不复制会话历史、附件、仓库或凭据。
- 对等凭据作用域为主机，通过插件页面或邀请配置。不提供单个浏览器会话撤销。
- 环境面板显示分布式团队和远程会话控件。普通对话标签页和本地 Agent Teams 名册仍属于本机。
- 保留的团队、任务和命令回执有显式上限。不自动淘汰历史或删除团队；团队操作预算耗尽后，应创建新的负责人 Session。

<a id="dev-note"></a>
### 开发备注

[实现计划](../../../docs/scratch/multi-machine-plan.zh.md)记录预期部署与验收范围。五个隔离的环回环境是集成测试夹具，不代表已经部署了五台物理机器。

**运行时不变量：** 不发布配套检查器。协调者记录是工具和投递读取的权威值；接收方直接从 Session 投影读取接收证据。锁互斥、清理和跨主机投递通过 Loader 与 HTTP 集成测试验证，而不是由仅检查服务是否存在的安装器验证。
